# Simplify

> Less is more.

Keep it simple.

Follow **KISS** and **YAGNI**:

- prefer the smallest clear solution;
- avoid unnecessary abstractions and dependencies;
- do not build features before they are needed;
- favor readable, maintainable code over cleverness.

This principle applies to both implementation and presentation:

- show only the information needed for the current context;
- prefer concise labels over permanently visible explanations;
- keep useful supporting information available, but reveal it on demand;
- use progressive disclosure for descriptions, help text, advanced options, and other secondary information;
- avoid overwhelming the user with information simply because it is available.

For example, a field should normally show its label directly. A longer description can remain available through a help control or expandable detail when the user needs it.
