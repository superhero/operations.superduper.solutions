# Browser-local model families

Selecting or reselecting a language model loads it automatically; opening a menu or page does not download weights. Enter submits the editable prompt; Shift+Enter adds a line. Inference runs in the browser, with the existing application tools and credentials/execution boundaries.

Open **Settings → AI** for language configuration, speech input, decision models, tools and compatibility details. The composer configuration shortcut opens that same section. Chat and Settings share one live session: switching preserves messages, drafts, attachments and loaded models. Unload the language model in either view before changing its configuration. Speech diagnostics initialize on first AI use; leaving both chat and AI Settings retains the existing microphone stop policy.

The canonical [language catalog](../src/lib/assistant/language-profiles.json) includes Bonsai2 (2B/4B/9B/27B), Ornith1.5 9B (Q4_K_M/Q8_0), Gemma4 E2B and MiniCPM5~2.52B. It retains exact publisher revisions, files, representations, runtime sources and acceptance attempts. Language profiles are text-only; WebML receives explicit `mmproj:null`. Gemma uses LiteRT-LM0.18.0 GPU_ARTISAN with greedy decoding, context4096 by default, reasoning and prefix caching off. Ornith and MiniCPM retain the native Wllama tool parser. Ornith weights cannot fit the four-GiB CPU heap. MiniCPM's automatic allocation fallback uses eight GPU layers before an eligible CPU retry; network/format errors never trigger placement or precision substitution.

The separate **MiniCPM5 · 2.52B · FP32** option uses the official Q4_K_M file with the pinned compatible Wllama JS/Wasm pair, full GPU model execution and FP32 activations/KV. It needs verified FP32 WebGPU plus native Wasm features, without requiring shader-f16. Context/output are capped at4096/256, greedy decoding, reasoning/prefix caching/flash attention/context shifting off. It rejects CPU/hybrid fallback and requires positive current-turn GPU computation with zero CPU model kernels. Mixed publisher quantization is retained; this is not uniform INT4. One real Operations skill/application/image task passed the exact combined answer and physical text restoration with FP16 unavailable. The original suite retained a premature immediate-unload assertion failure; later disposal/termination and terminal cleanup were observed. [Compatible text evidence](assistant-compatible-text-quality.json) preserves those separate outcomes and qualification limits. The original MiniCPM profile is unchanged.

Every Pi forward budgets its complete current system prompt, history, reasoning, tools and results before generation. Bonsai uses the pinned session's native `count_tokens` after any required cache reset, on the same session and template as generation. Its prompt count already includes images and full cached occupancy. Output is capped to the smaller configured/native context minus input and an explicit 128-token application reserve.

Current Gemma/Wllama JavaScript bindings have no prospective native request counter. Their safeguard estimates the full serialized request from UTF-8 bytes and message framing; the UI identifies this as an estimate, which cannot guarantee native token fit. Native formatters still enforce capacity. Overflow leaves history and completed tool effects intact and reports a visible limit; it never silently truncates history or repeats completed tools. Context feedback distinguishes native counts from estimates. [Recorded context checks](assistant-context-quality.json) include native Bonsai2B parity with cache off/on, zero counter dispatch, overflow refusal and cancellation/restart; other model sizes and devices are not newly qualified.

The [LFM2.5-VL1.6B image tool](../src/lib/assistant/vision-profile.json) receives original local image bytes. Only IDs/dimensions enter text prompts. It releases text, uses native512-square white letterboxing with context1024/greedy output256, disposes vision and restores the exact text settings while the Pi Agent/transcript/skills remain alive. The default Original FP16/Q4 runtime requires verified WebGPU shader-f16. Settings → AI → Image runtime also offers the pinned [Compatible FP32/Q4 profile](../src/lib/assistant/vision-compatible-profile.json): official Q4 vision/decoder matrices, FP32 embeddings/activations, context1024 and output128. It requires verified FP32 computation and at least nine storage buffers per shader stage; this check runs before releasing text. Each compatible session binds the owned GPU device. CPU shape/indexing/preprocessing operators remain enabled; positive device dispatches do not establish per-operator placement. The approximately2.02GB download is a file-size total, not a memory estimate. Whole model-file checksum verification is not yet an Operations installer guarantee. [Operations vision checks](assistant-vision-quality.json) confirm owned-device computation, cancellation, cleanup and a real skill/application/image tool round trip. Fresh code reading passed in that application case; the 2B language model still failed the exact combined answer. The separate four-digit OCR case also failed, so general OCR accuracy is not established. Conversations retain at most three images of up to10MiB/16MP. New conversation clears them. Gemma/MiniCPM image requests default to20 minutes total with three-minute text turns. Cancellation or unknown/failed cleanup can leave text unloaded. Speech capture/finalization and model computation are serialized; speech ORT1.30 and vision's pinned ORT1.31 stay separate.

The [decision catalog](../src/lib/assistant/decision-profiles.json) offers D3 lite0.8B BF16/nano2B Q8/mini4B Q8/flash9B Q8; Strands2B INT4 CPU and WebGPU; KnowLine Gen5.5 4B Q8; Elephant-1 9B Q4_K_M; and Perplexity Flash4B Q8. Expand Settings → AI → Decision models. Language and decision models hand off the local runtime automatically. A paused model restores its frozen settings before its next request; the chat transcript and completed tool results remain intact. Score decision sends one explicit state/question and never executes workflows. Results preserve native probabilities/confidence, raw diagnostics and preparation evidence. Confidence definitions differ by family.

Decision lifecycle is `load → prepare → validate → score → dispose`. One question named`q` uses yes/no, ordered choice or ordered score criteria. Exact formatted input is capped at1024 tokens. Guards reject native fitting/truncation and capacity loss before forward. KnowLine reserves a sample position and keeps read-twice/top64 checks; Elephant keeps complete prefix/suffix blocks; Perplexity keeps its interior marker/trailing tokens and protocol-v3 calibration. D3 uses the corrected four-GiB no-forward inspector and native SystemOne handler. D3-lite's template hash comes from accepted run`browser-decisions-1792919408113293110`. Strands keeps its pointer head, complete-versus-fitted input checks and explicit device binding. There is no generated-answer parser or application answer cache.

`build/assistant-runtime.mjs` emits optional workers separately. Native artifacts include receipts and public-source recipe inputs; npm packages are exact-pinned. Large Wasm uses transparent gzip asset responses, retaining decoded hashes. No weights or inference server are bundled. Development compiles its image worker in isolation using the same pinned package graph as production, caches successful bundles by source hash and refreshes them after source changes. This keeps page-only Vite diagnostics out of the worker. Other runtime assets use built files or installed pinned packages. Same-origin COOP and credentialless COEP establish cross-origin isolation.

Reference acceptance is from the read-only `llm-sds-01` browser-assistant/decision reports. [Source provenance](../src/lib/assistant/reference-sources.json) and decision vendor records retain exact hashes. Operations checks adapter ABI/settings, real Pi swaps with controlled engines, request/result guards, rendered controls, actual worker imports, Wasm compilation and transport hashes without downloading models. These checks preserve reference acceptance and do not constitute new inference/performance measurements for every model/device. Loading establishes memory fit; mobile inference remains unqualified. [Dependency notices](../src/lib/assistant/NOTICES.md) accompany the runtime distribution.

Pages serves oversized native Wasm through six narrowly routed asset handlers. They stream precompressed static files with explicit browser decoding headers; all inference remains in the browser. The generated worker uses manual response encoding, preserving decoded native hashes and the 25MiB asset limit.

Runtime ownership uses a cancellable FIFO inside each owner and one Web Lock for resident models on this origin/browser partition. Cross-tab requests ask idle owners to release; active chat turns retain the lease through their entire Pi/tool/vision sequence. Nested image work borrows that scope. Physical text restoration starts fresh native state and recounts the full logical history; it does not repeat completed tools. Model selection and CPU/hybrid placement remain explicit.

GPU speech holds the same runtime from preparation through capture, final native inference and acknowledgement of the recording-store write. Waiting or denied microphone permission is cancellable without stopping another owner. After handoff, speech restores in a fresh worker before opening the microphone. Explicit CPU speech skips the GPU handoff. This is same-origin coordination, not a system-wide GPU lock. Normal unload waits for native disposal; a stalled or failed worker has a bounded termination fallback. Unknown native cleanup retains the lease until the owned worker is torn down.
