# Default service schemas

The application bundles 83 packs covering 36 providers and 17,963 HTTP operations,
alongside the two examples. Manage them in **Settings → Schemas**. Installation
loads API descriptions locally; it does not contact provider APIs or supply credentials.

## Scope decisions

- Google Cloud covers Compute and Storage; AWS covers S3 and Lambda; Azure covers
  Resource Manager Resources. Each provider publishes separate product contracts.
- Gemini uses Interactions; Hugging Face uses Inference Endpoints. These names do
  not imply every API offered by the provider.
- Bluesky uses official App/AT Protocol, chat and Ozone documents. Server selection
  distinguishes public AppView, relay and personal data servers.
- Docker and Azure Swagger documents are converted to OpenAPI 3; external
  references are bundled locally while retaining recursive references.
- DeepSeek and Dukascopy snapshots come from structured official documentation.
  Dukascopy retains procedure choices on its shared HTTP endpoint.
- Anthropic and Groq artifacts are identified by official SDK metadata. Missing
  version labels are explicitly supplied for Anthropic and Bluesky. The inventory
  retains provenance, including community conversions.

## Atlassian

The existing Bitbucket Cloud, Jira Cloud platform and Confluence Cloud v2 catalogs
use the `Atlassian / …` prefix. Their catalog IDs, operation IDs, source digests
and discovery data remain unchanged. Factory labels refresh without replacing
user-authored names or saved enablement and ordering.

The collection also includes published contracts for Jira Software and Service
Management, Confluence v1, Trello, Statuspage, Opsgenie, Compass REST, Assets,
Automation, Focus, Forms, Incidents, Customer Service Management, Capacity
Planning, administration, backup management, Commerce, Marketplace, migration,
privacy and consent, security vulnerability reporting, Teams, Forge storage and
Forge containers. Data Center contracts cover Bamboo, Bitbucket, Confluence,
Crowd, Jira Software and Jira Service Management. These are the published API
profiles, not a claim that every product capability has a REST endpoint.

Confluence v1 and v2 expose complementary resources. Marketplace product tags use
a separate v3 contract alongside the main v2 API. Jira Data Center product
contracts share core resources; both complete product contracts are retained.
The inventory follows Atlassian's public Cloud and Data Center API directories,
checked on 2026-10-20. GraphQL-only APIs are not converted into invented REST
contracts. No public, tenant-independent Jira Align contract was found; its
instance-specific Swagger export can be uploaded through Settings → Schemas.

Statuspage's original OpenAPI document is extracted from its embedded ReDoc JSON
state without executing page scripts. Opsgenie's official Swagger 2 document is
converted through the existing Swagger pipeline. New catalogs use method/path
operation IDs because several upstream specifications reuse operation IDs or
reference the same operation through multiple paths. Original IDs remain in
`x-upstream-operation-id`, and materialized path aliases retain
`x-upstream-path-ref`. Recursive request and response models remain references.

Published authentication requirements and server definitions are retained.
Basic authentication, private app-runtime credentials and instance configuration
still have the limitations described below; adding a catalog does not make an
unsupported authentication mechanism executable. No account access is granted
by installing these descriptions.

## FRED and ALFRED

FRED covers US and international economic data, not just a region. The Federal
Reserve Bank of St. Louis manages both FRED and ALFRED. FRED includes the 31 v1
economic-data endpoints, the v2 bulk-release observations endpoint and the four
existing GeoFRED endpoints. Existing FRED operation identifiers are retained.

ALFRED exposes the same 31 v1 economic-data endpoints as a separate catalog for
historical vintages and revisions. It uses the real `/fred` routes on
`https://api.stlouisfed.org`; there is no separate `/alfred` route or key.
Set `realtime_start` and `realtime_end` to a past date to retrieve data known on
that date, or use `vintage_dates` and `output_type` for observation revisions.
Without a historical period, most endpoints return the current vintage.

[Register a FRED API key](https://fredaccount.stlouisfed.org/apikeys), save it in
the vault, and select it for the operation's credential binding. The worker sends
v1 keys as `api_key` query parameters and v2 keys as bearer tokens. Public inputs
cannot override these parameters, and previews omit authentication values.
Both catalogs explicitly request JSON for structured workflow outputs. Observation
values remain strings because the API uses `"."` for missing values. V2 bulk
requests use `next_cursor` to retrieve subsequent pages; reduce `limit` for large
responses to stay within the worker's response-size limit.

The base v1 schema is community-maintained. The reproducible
`build/fred-schema.mjs` adaptation adds documented JSON response structures and
the official v2 contract; each economic operation links to its official API docs.

## Execution limits

Typed controls cover supported constraints. Advanced JSON schemas use a JSON
input with API-side validation. Unsupported authentication, serialization and
binary transports remain visible with an execution limitation. AWS signing is
unsupported. OAuth access tokens use bearer transport; login, token refresh and
scope acquisition are outside this feature.

Browser CORS and local-network restrictions still apply. Docker needs an HTTP
endpoint because browsers cannot use its Unix socket. Ollama must permit the
application origin. Account-specific server placeholders need configuration.
No provider credentials are bundled.

## Local ownership

Existing profiles receive missing defaults once. Deletions, enablement and order
survive reloads. Unmodified defaults follow packaged revisions; renaming,
replacement or history inspection creates a Git copy that updates do not overwrite.

See [OpenAPI adaptation](adr/openapi-adaptation.md) and the
[pack guide](../src/catalogs/services/README.md) for persistence and refresh details.
